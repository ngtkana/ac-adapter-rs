# Issue運用ルール

## 起票前の確認

- issue起票前に必ず `gh api repos/ngtkana/ac-adapter-rs --jq '.has_issues'` でIssues機能が有効か確認する
- 無効だった場合、勝手に有効化せずユーザーに確認する（有効化する/リポジトリ内Markdownで管理する/今回は記録しない、等の選択肢を提示する）

## ラベル

- 新規ラベルを作らず、既存ラベル（`gh label list`で確認）から選ぶ。適切なものがなければユーザーに確認する

## 起票のタイミング

- レビュー・調査で見つかった、今回のタスクのスコープ外の問題（例: PRのレビューで見つかった別ファイルの既存バグ）は、黙って見送らずissueとして起票する
- issue本文には「発見経緯」（どのPR/作業で見つかったか）を書き、文脈が失われないようにする
